# Issue 48 - Implement CVN PDF XML Extraction

## Summary

Issue `#48` implements deterministic extraction of CVN XML from FECYT-generated
PDF files when the XML is embedded or available in PDF metadata.

This issue is part of epic `#41`.

## Goal

- support CVN PDF import through embedded XML extraction
- avoid OCR or LLM reconstruction in the first deterministic parser path
- report unsupported PDF cases clearly

## Background

The TFG mentions importing curricula generated by FECYT. A practical first step
is to inspect whether the PDF contains embedded XML or metadata that can be
extracted deterministically. PyMuPDF exposes PDF embedded-file and XML metadata
APIs such as embedded file counts, names, extraction, and XML metadata access.

## Planned Steps

1. collect or identify safe sample FECYT CVN PDFs for testing
2. inspect whether sample PDFs contain embedded files
3. inspect whether sample PDFs contain XML metadata
4. extract candidate XML payloads deterministically
5. validate extracted XML shape before passing to XML import
6. integrate extraction with parser contract from issue `#47`
7. define clear errors for PDFs without extractable XML
8. add tests with fixtures when sample files are available and safe to commit

## Expected Output

- PDF extraction helper or parser implementation if approved
- documented extraction behavior
- tests for PDF with extractable XML when fixture exists
- explicit unsupported-path behavior for PDF without XML

## Verification

- extractable PDF fixture yields XML bytes or text
- extracted XML can be passed to XML parser path
- PDF without XML returns structured unsupported error
- no OCR or LLM fallback is silently attempted

## Known Risks

- FECYT PDFs may not consistently embed XML
- available test PDFs may contain personal data and may not be committable
- extraction behavior may differ across PDF versions

## Impact On Later Issues

- issue `#49` consumes extracted XML through the XML validation path
- epic `#51` uses PDF import through the parser contract
